세팅 메뉴 실행 순서 (새 씬에서 처음부터)

Unity 상단 메뉴 LionIceRun에서 위에서부터 차례로 실행한다. 모든 메뉴는 여러 번 실행해도 안전하다.

  1. Step 2 맵 세팅 → Step 2 바다 꾸미기
  2. Step 3 플레이어 세팅
  3. Step 4 얼음 깨짐 세팅 → Step 4 얼음 그래픽 세팅
  4. Step 5 생존 시간 세팅 → Step 6 게임 매니저 세팅
  5. Step 8 캐릭터 가져오기 (먼저 Tools/blender/build_all.ps1로 FBX 출력)
  6. AI 봇 세팅 → 시련·보상 세팅
  7. Step 7 UI 세팅 (마지막에. 처음엔 TextMeshPro 리소스를 가져온 뒤 한 번 더 실행. 직접 고친 배치는 유지되고, 되돌리려면 "배치 초기화")
  8. 맵 선택 화면 세팅 (타이틀·시작하기 버튼·맵 선택 화면 생성 + JSON 맵 미리보기 스크린샷 일괄 촬영. 맵 추가·수정 후 맵 미리보기 스크린샷 다시 찍기)
  9. 친구 멀티 세팅 (Play를 끄고 실행. 타이틀 시작하기 → 혼자 하기/로비 만들기/코드로 참가. OnlineUI와 OnlineNetwork, OnlinePlayer 템플릿을 씬/프리팹에 저장. 재실행 시 기존 OnlineUI 위치·크기 보존)
  10. 밀치기·이름표 업데이트 (Play를 끄고 Main 씬에서 실행. 플레이어와 OnlinePlayer 프리팹에 강화 수치·이름표 저장. 기존 이름표 위치·크기는 보존. 친구 멀티 세팅에도 포함)
  11. 카운트다운·밀치기 효과 업데이트 (Play를 끄고 실행. 중앙 220pt 카운트다운과 밀치기 입자 설정을 씬/플레이어/OnlinePlayer에 저장. 이전 이름표·강화 수치도 포함. 기존 효과·카운트다운 사용자 배치는 보존)
  12. UI 폴리싱 (Play를 끄고 Main 씬에서 실행. 닉네임/방 코드 입력창 대비·한글 조합 태그 수정, 실제 모델과 좌우 화살표 선택, 로비 모델 초상화, 화면별 색상·버튼 반응을 저장. 최초 모드 선택 화면은 2열로 재배치하고 이후 사용자 배치와 기존 게임 HUD 위치·크기는 보존. 빌드는 사용자가 요청할 때만 진행)

중앙 카운트다운은 MatchCountdown으로 솔로·멀티에서 공유한다. 경기 시작/로비 복귀 시 숨기고 입력을 가리지 않는다. PushVfx는 앞쪽 흰색/하늘색 입자를 20개 방출하며, 멀티에서는 기존 밀치기 경과 시간 스냅샷으로 중복 방출 없이 재생한다. 씬/프리팹 메뉴 결과·참조·재질 등 검사 소스와 결과는 Tools/tests/online-effects/에 보관한다.

UI 이미지를 다시 만들려면 Tools/ui/slice_ui.ps1, 캐릭터·펭귄을 다시 만들려면 Tools/blender/build_all.ps1.

시련

솔로 플레이의 긴장감을 위한 방해 요소. 플레이어와 AI 봇 모두에게 적용된다. 구현: Assets/Scripts/Trials/ (메뉴 LionIceRun > 시련·보상 세팅).

원칙

  • 모든 시련은 미리 예고해서 피할 수 있게 한다.
  • 버틴 시간이 길어질수록 시련이 하나씩 추가된다.
  • 시련이 플레이어가 서 있는 블럭을 예고 없이 바로 깨뜨리지 않는다.
  • 맞으면 폴가이즈처럼 넘어지거나 밀려나는 우스꽝스러운 결과가 나온다.

  • 모든 시련은 예고 뒤에 일어나서 피할 수 있다. 처음 나올 때 한 번 안내 문구가 뜬다.

  • 기절한 동안에는 오래 서 있기 타이머를 멈춘다.

친구 멀티플레이 설계와 구현 (2026-10-06)

기본 방향

친구 2~4명이 비공개 로비에 모여 현재의 맵 카드 룰렛과 생존 경기를 함께 진행한다. 방장 PC가 서버 역할도 맡는 호스트 권한 방식. 친구 초대·참가는 방 코드 공유로만 진행하는 것으로 확정했다. Steam 출시는 현재 계획에 없으며 플랫폼 친구 목록·초대 연동은 작업 범위에서 제외한다. 싱글 플레이는 기존 AI 경기 흐름을 유지한다. 첫 버전은 사람 최대 4명, 봇 포함 기본 참가자 4명이다. 방장이 빈자리 봇 채우기를 켜거나 끌 수 있으며 신중형·공격형 비율을 설정한다. 호환 네트워크 패키지를 고정하고 방 코드 접속·경기 코드를 작성했다. 씬 연결은 Play를 끈 뒤 LionIceRun > 친구 멀티 세팅으로 저장한다.

화면과 진행 흐름

타이틀기존 바다·동물·로고를 유지. 시작하기 → 혼자 하기 / 로비 만들기 / 코드로 참가. 닉네임·스킨 선택, 연결 중·오류·다시 시도 표시
로비 생성방 이름, 최대 사람 수(2~4), 봇 채우기·유형 설정. 비공개 방을 만들고 방장을 첫 슬롯에 등록
로비 대기캐릭터 슬롯·닉네임·스킨·방장 표시·준비 상태, 빈자리 초대 표시. 방 코드와 복사 버튼, 준비/준비 취소, 나가기. 방장에게 경기 시작 버튼. 새 참가자만 준비 전으로 추가하고 기존 참가자의 준비는 유지
친구 초대방 코드 복사 → 사용자가 친구에게 공유 → 친구는 타이틀의 코드로 참가에서 입력. 친구 초대·참가는 이 방식으로만 제공하며 게임 밖 메시지는 사용자가 직접 공유
시작 조건사람 최소 2명, 모든 참가자 준비·네트워크 접속 완료·공통 유효 맵 존재. 조건이 맞아야 방장 시작 버튼 활성화. 참가자/설정 변경 시 준비 해제. 시작 요청을 수락하면 참가를 잠그고 명단 확정
맵 선택모든 참가자에게 같은 순서·같은 시간의 카드 표시. 방장만 멈추기 가능, 다른 사람은 방장이 맵을 고르는 중 안내. 중복 시작·멈추기 요청 차단
맵 로딩선택 결과와 맵 해시 확인, 전체 로딩 완료 응답 대기. 시간 초과·참가자 이탈은 시작 취소 후 로비 복귀. 완료 후 서버 시각 기준 3·2·1과 동시 경기 시작
경기각자 자신의 캐릭터 조작·카메라 추적. 사망 시 자신의 화면만 흑백과 우측 부활 안내. 다른 사람·봇의 닉네임과 부활 남은 시간 목록
결과모두 같은 순위·우승자 표시. 다시 준비 → 같은 로비로 복귀, 다음 경기에서 맵 다시 선택. 나가기 → 타이틀. 참가자 개인의 R 키는 멀티 경기 재시작 권한 없음

서비스와 실행 구조

Unity Multiplayer Services SDK의 Sessions로 방 생성·참가·명단·속성을 관리하고, Unity Authentication으로 참가자 ID를 만든다. 첫 버전은 익명 인증과 닉네임, 프로필 연결은 이후 확장. Unity Relay로 인터넷 연결을 중계하고 Netcode for GameObjects + Unity Transport로 경기 상태를 동기화한다. Relay는 연결 중계이며 물리 판정 서버는 방장 PC다. 구현 시 Unity 6000.6과 호환되는 패키지 버전을 확정·고정하고 Unity 프로젝트 연결 및 UGS 환경 설정을 별도 진행한다.

현재 구현은 기존 Main 씬을 유지하고 그 안에서 로비·룰렛·경기 맵과 참가자를 재구성한다. 멀티 경기에서는 씬 재로드를 하지 않아 세션 접속을 유지한다. OnlineGameSession이 MPS와 NGO 연결·경기 진행을 맡고 OnlineFrontend는 타이틀 모드 선택·로비/결과 표시를 맡는다. NGO CustomMessagingManager로 참가자 생성 정보와 물리 상태를 전달하며, 각 PC가 동일한 OnlinePlayer 템플릿에서 참가자를 만들고 호스트만 물리를 실행한다. NGO NetworkObject 자동 생성·NetworkTransform·네트워크 씬 관리는 사용하지 않는다. 로비/룰렛에서 전체 Time.timeScale = 0 대신 경기 상태로 시뮬레이션과 입력을 제한한다. 기존 UI 배치는 에디터에서 생성·저장 가능하게 한다. 추후 씬 분리는 필요할 때 진행한다.

동기화와 판정

플레이어 입력·이동소유 클라이언트가 이동 벡터·점프/다이브/밀치기 입력과 순번을 보냄. 호스트가 소유권·현재 상태·쿨타임·입력 범위를 검사하고 물리 계산. 이동 입력은 최신 순번만 적용하고 연결/입력 중단 시 중립 입력. 단발 입력은 중복 실행 방지
캐릭터 물리호스트에서 Rigidbody 충돌·넉백 계산, 참가자는 위치·속도·상태를 받아 보간. 우선 30Hz 네트워크 전송·50Hz 물리 시작값. NGO 컴포넌트만으로 입력 예측이 자동 완성되지는 않으므로 100~150ms 지연에서 검증하고 필요하면 로컬 이동 예측·서버 보정 별도 구현
얼음 칸호스트만 밟음·시간 경과·금 감·파괴·복구 계산. 현재는 같은 JSON의 x/z 생성 순서에 맞춰 칸별 단계 한 글자씩 묶은 전체 스냅샷을 5Hz로 전송 (15×15 최대 225글자). 신뢰성 있는 순서 보장 메시지로 보내고 라운드 번호를 검사한다. 참가자는 판정 타이머를 독립 실행하지 않음. 변경분 전송은 이후 트래픽 측정 뒤 최적화
AI호스트만 BotBrain 실행. 사람/봇 공통 템플릿에서 생성하고 참가자는 확정된 동작을 받음. 사람과 봇 모두 같은 참가자 ID 체계
시련·아이템호스트만 방향·위치·종류·시작 시각·피격·생성·획득·소멸 결정. 예고는 서버 시각으로 표시. 아이템은 모든 사람에게 획득 가능, 봇은 기존처럼 제외. 동시에 먹으면 호스트에서 최초 유효 획득 1건만 적용
경기·부활·결과호스트가 시작/종료 시각·탈락·부활 예정 시각·자리 대기·순위를 관리. 기존 10초 부활·맵 위 1명 시 종료 규칙 유지. 같은 물리 틱의 낙하를 모두 반영한 뒤 종료 판정, 동시 순위는 서버가 확정하고 모두 동일하게 표시
UI·그래픽카메라·조작 안내·흑백·화면 애니메이션은 로컬. 얼음 파편·물보라·소리 등 판정 없는 연출은 확정된 사건을 받아 재생. 로컬 우승 횟수와 솔로 최고 기록은 멀티 기록과 분리

맵 선택과 시작 위치

첫 버전은 각 빌드에 포함된 JSON·PNG 사용. 참가자가 맵 ID와 정규화된 내용의 해시를 제출하면 호스트가 모두에게 공통인 맵만 후보로 정한다. 파일명이 같아도 지형이 다르면 제외하고 공통 맵이 없으면 시작 차단·버전 안내. 후보 순서·룰렛 시작 서버 시각·속도·감속 시작 시각·최종 정렬 위치·선택 맵을 호스트가 전송한다. 클라이언트는 공통 시간으로 애니메이션을 계산하고 최종 선택은 호스트 결과를 따른다. 매 프레임 카드 위치를 보내지 않는다.

시작 칸은 호스트가 playerStart와 botStarts를 통합 배치 후보로 사용해 사람부터, 다음 봇 순서로 배정한다. 중복·빈칸·위험 칸을 제외하고 부족하면 연결된 안전한 내부 칸을 보충한다. 참가자별 칸과 스킨·봇 유형을 명시적으로 전송하며 각 PC가 무작위로 다시 뽑지 않는다. 지형 부족 시 참가자를 겹치게 생성하지 않고 로딩을 취소한다. 사용자가 새로 만든 커스텀 JSON·사진을 친구에게 자동 전송하는 기능은 후속 확장이다.

연결 실패와 첫 버전 범위

잘못된 코드·정원 초과·진행 중인 방·다른 프로토콜 버전·접속 시간 초과를 구분해 안내하고 중복 연결 요청을 막는다. 실패/취소 시 세션·네트워크 자원을 정리한다. 경기 시작 전 이탈은 명단에서 제거하고 모두 준비 해제. 경기 중 일반 참가자 이탈은 기권 처리, 이번 경기에는 재접속·AI 대체 없음. 방장 연결 종료는 경기 종료 안내 후 타이틀 복귀, 호스트 자동 이전은 후속 기능이다. 로비 소유권 이전과 진행 중인 물리 서버 이전은 별도이며 SDK의 세션 기능만으로 경기 상태 복구가 완성되는 것으로 간주하지 않는다. 진행 중 참가·공개 매칭·음성 채팅·클라우드 순위도 후속 기능이다.

첫 번째 완료 기준은 서로 다른 PC/인터넷에서 코드로 참가한 2명이 이동·점프·밀치기·같은 얼음 파괴를 확인하는 것이다. 로비 UI부터 전체를 연결하기 전에 물리 동기화 위험을 검증한다. 그 다음 맵 룰렛과 4인 준비/시작, 부활·시련·아이템·결과·반복 경기 순서로 확장한다. 지연 50/100/150ms·패킷 손실 1~3%, 동시 밀치기/아이템 획득/낙하, 로딩 중 이탈, 방장 종료, 15×15 맵 반복 경기와 솔로 회귀를 검증한다. UGS 이용량·비용은 실제 인원/트래픽 측정 후 결정하며 설계 단계에서 무료 운영을 전제하지 않는다.

공식 근거: Unity Multiplayer Sessions, NGO 물리 동기화. Unity 공식 레지스트리에서 Unity 6000.6 호환성을 확인해 NGO 2.13.3, Multiplayer Services 2.3.3, Authentication 3.7.0을 manifest에 고정했다. 별도 검증 프로젝트에서 실제 패키지 설치·컴파일·Windows 검증 빌드 성공. 프로젝트 ID는 기존 연결을 유지하며 Dashboard 서비스 설정은 변경하지 않았다.

할 일 목록

미정 사항

  • 시련 시작 시간 (눈덩이 15초 / 찬바람 30초 / 고드름 45초 / 펭귄 60초, 플레이 테스트로 조정)
  • 얼음 깨짐 수치 (기본값: 3번 밟으면 흔들림, 흔들림 1초 뒤 깨짐, 오래 서 있기 2초, 조정 가능)
  • 얼음 미끄러짐 적용 여부 (Thin Ice는 미끄러움, 선택)
  • 게임 시작 시 처음부터 빈칸을 둘지 여부
  • 펭귄 슬라이딩: 깨진 블럭(빈칸)을 지날 때 → 우선 추천안(그대로 미끄러져 지나감)으로 구현함. 바꾸려면 요청
  • 1등 규칙: 봇 0마리(혼자)일 때는 떨어지면 바로 끝남 (1등 없음). 봇 수·다시 들어오는 시간은 플레이 테스트로 조정
  • 시련(눈덩이·찬바람 등) 시작 시간은 이제 "경기 시간" 기준. 경기가 짧아지면 앞당길지 결정
